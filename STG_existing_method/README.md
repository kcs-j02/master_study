# STG_existing_method

Green Contextを使わない既存手法の比較評価用コードである。タスクの依存関係を保ちながら、bottom levelと予測完了時刻に基づいて、複数の通常CUDA streamへタスクを静的に割り当てる。

## 処理の流れ

1. STGファイルを読み込み、タスクの依存グラフ（DFG）を構築する。
2. 現在の入次数が0であるタスクを同じレベルへ格納し、後続タスクの入次数を減らしてレベル化する。
3. 最大レベル幅と上限5本のうち小さい値をstream数とする。
4. 各タスクについて、自タスクから出口までの経路上にあるタスクの処理時間和の最大値（bottom level）を計算する。
5. 全先行タスクが割当て済みのタスクをready集合に入れ、bottom levelが大きいタスクから選択する。同値の場合は、処理時間が大きいタスク、タスクIDが小さいタスクの順に優先する。
6. 各streamについて、全先行タスクの予測完了時刻の最大値以降にタスクを挿入できる最初の空き区間を探す。その中から、原則として予測完了時刻が最小となるstreamを割当て先に選ぶ。
7. 予測完了時刻が同じ場合は、最も遅く完了する先行タスクと同じstreamを優先する。また、現在の部分makespanを悪化させない場合はstream 0へ配置し、空き区間を密に埋める。
8. 割当て結果に従って通常CUDA streamを作成し、TaskflowとCUDA EventによってDFGの依存制約と同一stream内の予測開始時刻順の実行を保証する。これにより、依存待ちタスクの先行投入によるhead-of-line blockingを防ぐ。

## stream数

stream数 $S$ は次式で決定する。

```text
S = min(最大レベル幅, 5)
```

複数のstream数候補に対するmakespanを比較するのではなく、上式により1つの構成を選ぶ。

## タスクの優先度

タスク $i$ の処理時間を $p_i$、直接後続タスク集合を $succ(i)$ とすると、bottom level $bl_i$ は次式となる。

```text
bl_i = p_i + max(bl_j),  j in succ(i)
```

後続タスクを持たない場合は $bl_i = p_i$ である。bottom levelが大きいほど、出口までの残り処理時間が長いため、ready集合から先に割り当てる。

## 特長

- 依存関係を満たすタスクだけを選ぶ静的ready-list schedulingである。
- bottom levelにより、出口までの残り処理時間が長いタスクを優先する。
- earliest-finish-time型のstream選択により、各タスクの予測完了時刻を早める。
- streamの末尾だけでなく、依存待ちで生じた空き区間にもタスクを挿入できる。
- Green Contextの作成やSMの事前分割を必要としない。

## 制約

- 割当て時には各streamに同じ参照SM数114を与える。この値は予測用であり、streamごとの専有SM数ではない。また、予測で用いる各タスクの実効SM数は最大64に制限する。
- 実行時は全通常streamがGPU資源を共有し、streamごとの専有SM分割は行わない。そのため、複数カーネルの同時実行時に発生する資源競合は予測に反映しない。
- 通信時間、データ転送時間、および実行中の動的な再スケジューリングは扱わない。

## Existing + GCとの違い

`STG_existing_method_GC`は、上記と同じタスク選択、stream数、stream割当てを使用する。割当て確定後に全streamをGreen Context上に作成し、使用可能なSMを分割粒度の範囲でほぼ均等に配分する。

GCのSM配分を決めた後もタスクの再割当ては行わず、実行中にSMを再配分することもない。
